# 미니게임 진행 순서

> 규칙과 설계는 `docs/minigame_plan.md`, 구조는 `docs/minigame_structure.md`.
> 단계 하나 = PR 하나. 끝난 항목은 `[x]`로 바꾸고 PR 번호를 적는다.

## 순서를 정한 이유

복잡도가 낮은 것부터 하나씩 새 능력을 더해 가도록 했다. 앞 단계에서 만든 공통 기반을 다음 게임이 그대로 쓴다.

| 단계 | 게임 | 새로 필요한 능력 |
|---|---|---|
| 0 | 공통 기반 | 게임 종류 저장, 점수제, 공통 대기실·순위표 |
| 1 | 블라인드 경매 | 숫자 입력, 사람별 자원(칩) |
| 2 | 빨강 / 파랑 | 과반 게이지 연출, "범인 공개" 연출 |
| 3 | 가장 작은 유일한 숫자 | 판 형태 공개 연출 |
| 4 | 인디언 숫자 | 사람마다 다르게 보이는 비밀 정보 |
| 5 | 라이어 다이스 | 차례 진행(턴제) |

## 진행 상황

### 0단계 — 공통 기반 (PR: feature/minigame-foundation)
- [x] SQL: `game_rooms.game / settings / state`, `game_players.data`, `game_moves` 테이블, 상태 `playing` 추가 (여러 번 실행해도 안전) — **배포 전에 Supabase에서 실행 필요**
- [x] 방 만들 때 게임 종류·설정 기본값 저장 (`DEFAULT_GAME` 제한 해제)
- [x] 공통 대기실(`shared/lobby.js`)·참가 화면(`shared/join.js`)으로 분리하고 소수결을 옮김
- [x] 서버 공통 도구: 제출·조건부 마감(`round.js`), 순위 계산(`scoreboard.js`), 시상식 고르기(`awards.js`), 설정 검사(`settings.js`)
- [x] 화면 공통 로직(`shared/logic.js`): 늦게 온 응답 무시, 순서대로 보내기, 문구 고르기·채우기
- [x] 웃음 장치(`shared/fx.js`): 카운트다운, 도장, 호외 헤드라인, 이름표 떨어지기, 효과음(끄기 가능)
- [x] 소수결에 웃음 장치 적용: 호외 헤드라인, 생존·탈락·우승 도장, 탈락자 이름표 떨어지기, 휴대폰 도장·진동
- [x] 진행자 설정을 대기실에서 바꾸기 (화면·서버 검사. 실제 설정이 있는 게임은 1단계부터)
- [x] 테스트 틀: 단위(`node --test`), SQL(PGlite), 화면(Playwright), 뮤테이션(Stryker, 95% 기준), PR마다 자동 실행
- **완료 기준**: 소수결이 새 공통 기반 위에서 기존과 똑같이 동작하고, 기존 테스트가 모두 통과 → 충족 (단위 130, SQL 6, 화면 17, 뮤테이션 99.63%)
- 1단계로 넘긴 것: 순위표 화면, 최종 시상식 화면, 하나씩 공개하는 슬로모션 연출 (서버 계산은 0단계에서 완료, 화면은 처음 쓰는 경매에서 만든다)

### 1단계 — 블라인드 경매 (PR: feature/blind-auction)
- [x] 0단계에서 넘어온 화면 도구: 공통 순위표(`shared/scoreboard.js`), 최종 시상식(`shared/awards.js`), 시간표대로 연출하기(`fx.timeline`)
- [x] 뮤테이션에서 남은 4개 잡기 (설정 저장 응답, 다른 게임 전용 요청 거절)
- [x] 규칙 엔진 + 단위 테스트 (최고액 동점, 미제출 0, 칩 0, 저주 물건, 미스터리 상자, 최종 동점)
- [x] 물건 41개와 잉크선 그림 (일반 1~3점, 미스터리 상자 0~5점, 저주 물건 −2점)
- [x] 경매장 화면(`auction/stage.js`): 일정표, 손이 봉투를 밀어 넣고 바꿔치기, 금액 순서대로 칩 밀기, 공중분해·저주 떠넘기기·상자 열기·헐값 낙찰
- [x] **휴대폰만으로 진행** (기본): 방장 휴대폰이 진행하며 참가. 공개 연출을 모든 휴대폰에서 서버 공개 시각 기준으로 같은 순간에 재생. PC 화면은 선택
- [x] 글 줄이기: 규칙은 기호(↑ 최고가 / ↓ 최저가), 물건은 그림, 첫 화면은 그림 세 칸
- [x] Playwright: PC 2명·6명 끝까지, 휴대폰만 3명 끝까지, 늦게 연 휴대폰 이어보기, 비밀 유지, 새로고침, 응답 지연 3종
- **완료 기준**: 2명과 6명으로 끝까지 진행되고 최종 순위가 맞음 → 충족 (기본 10라운드 대신 테스트는 5라운드)
- 다음으로 넘긴 것: 소수결도 휴대폰만으로 진행 (경매에서 만든 방식을 그대로 옮김)

### 2단계 — 빨강 / 파랑
- [ ] 규칙 엔진 + 단위 테스트 (과반 경계: 짝수·홀수 인원, 미제출 포함 분모)
- [ ] 진행 화면: 과반선 게이지, 1표 차 슬로모션, 범인(빨강) 공개 / 참가 화면: 빨강·파랑 버튼
- [ ] Playwright: 3명, 10명
- **완료 기준**: 과반 경계(1표 차 성공/실패)에서 점수 계산이 맞고, 1표 차 실패 연출이 나옴

### 3단계 — 가장 작은 유일한 숫자
- [ ] 규칙 엔진 + 단위 테스트 (전부 겹침, 승자 점수 = 고른 숫자)
- [ ] 진행 화면: 1~10 숫자판 공개, 겹친 이름표 튕겨 나가기 / 참가 화면: 1~10 버튼
- [ ] Playwright: 3명, 15명
- **완료 기준**: 3명과 15명 모두 판정·점수가 맞음

### 4단계 — 인디언 숫자
- [ ] 칩 규칙 확정(#132): 승부 3 / 포기 1 / 최고 숫자 포기 벌칙 5. 정산 순서와 마지막 판 남은 칩 소멸(#133)을 순수 함수 테스트로 고정 (계획서 3-4의 예시 표 두 개를 그대로 테스트로: 시작 칩 1·2·3·4개, 교체 유무, 승부/포기, 모두 포기, 정산 전후 칩 합계 보존)
- [ ] 비밀 정보 응답 설계: 본인 숫자는 응답에 절대 포함하지 않음 (보안 테스트 포함)
- [ ] 규칙 엔진 + 단위 테스트 (판 이월, 칩 부족, 탈락, 포기 벌칙, 최고 숫자 포기 벌칙, 모두 포기)
- [ ] 라운드 두 단계 진행: 교체 단계 → 승부/포기 단계 (진행자가 넘김)
- [ ] 덱: 1~10 여러 벌(인원별 2~5벌), 쓴 카드 버림, 남은 카드가 인원×2 미만이면 다시 섞기
- [ ] 나온 카드 기록판 (교체로 버린 카드는 바로 공개)
- [ ] 카드 교체: 칩 1개, 라운드당 1번, 덱에서 새 카드 (10명 전원 교체 테스트)
- [ ] 동점 처리: 승자 여러 명이면 판·벌칙 나누고 남은 칩 이월
- [ ] 진행 화면: 판의 칩, 단계, 교체·결정 현황, 순차 공개(포기자 숫자 마지막), "10 들고 도망감" 벌칙 도장 / 참가 화면: 남의 숫자, 가려진 내 카드, 교체, 승부·포기
- [ ] Playwright: 2명, 8명. 참가자 응답에 본인 숫자가 없는지 검사
- **완료 기준**: 어떤 응답에도 본인 숫자가 공개 전까지 나오지 않고, 덱 셈(기록판)이 실제 나온 카드와 일치

### 5단계 — 라이어 다이스
- [ ] 차례 진행 도구: 현재 차례, 다음 차례, 진행자 차례 넘기기
- [ ] 규칙 엔진 + 단위 테스트 (부르기 크기 비교, 판정, 탈락, 새 판 시작 순서)
- [ ] 진행 화면: 차례·부른 기록·남은 주사위, 컵 엎기 공개, 피노키오 코·생사람 잡기 연출 / 참가 화면: 내 주사위, 부르기, 의심(내 차례만)
- [ ] Playwright: 2명, 6명, 자리 비운 사람 차례 넘기기
- **완료 기준**: 마지막 1명이 남을 때까지 진행되고, 비밀 주사위가 본인 외에 노출되지 않음
