# 미니게임 계획서 — 같이 하는 게임 5종

> 진행 순서와 진행 상황은 `docs/minigame_roadmap.md`에서 관리한다.
> 현재 구조와 게임 추가 방법은 `docs/minigame_structure.md` 참고.

## 1. 목표

- PC(진행 화면) + 휴대폰(참가) 방식의 같이 하는 게임을 소수결 외에 **5종** 더 만든다.
- **2~15명**의 적은 인원에서도 쫄깃한 게임을 우선한다.
- 모든 게임은 한 방(방 코드·QR·대기실)을 공유하는 같은 틀 위에서 돌아가게 한다.
- **모든 게임은 기본적으로 코믹하다.** 이기고 지는 순간에 웃음이 터지는 장치를 반드시 하나 이상 둔다.

## 2. 공통 원칙

| 항목 | 원칙 |
|---|---|
| 진행 | 대기실 → 라운드 반복 → 최종 순위. 진행자(PC)가 시작·공개·다음 라운드를 누른다 |
| 입력 | 참가자는 휴대폰으로 **몰래** 고른다. 공개 전까지 바꿀 수 있다 |
| 공개 | PC에서 3·2·1 뒤 공개. 게임마다 하나씩 차례로 보여주는 연출을 둔다 (긴장감의 핵심) |
| 마감 유예 | 공개 버튼 후 1초 뒤에 마감한다 (소수결에서 검증된 방식) |
| 점수 | 소수결 외에는 **점수제**. 라운드마다 PC에 순위표, 휴대폰에 내 점수·순위 |
| 비밀 정보 | 사람마다 다르게 보이는 정보(주사위, 카드)는 **휴대폰에만** 표시. PC 화면에는 절대 표시하지 않는다 |
| 방식 제약 | 1.5~2초 폴링이라 "먼저 누르는 사람이 이기는" 규칙은 쓰지 않는다 |
| 라운드 수 | 게임마다 기본값을 두고, 진행자가 대기실에서 바꿀 수 있게 한다 |
| 디자인 | 지금 톤(종이 배경, 잉크색, 얇은 선, 장식 없음)을 유지한다 |
| 코믹 | 게임마다 웃음 포인트를 정한다. 웃음은 반짝이 효과가 아니라 **타이밍·움직임·문구**로 만든다 (아래 2-1) |

### 2-1. 웃음 장치 (공통)

종이·인쇄물 톤에 어울리는 장치만 쓴다. 네온, 반짝이, 화면 가득한 파티클은 쓰지 않는다.

| 장치 | 내용 |
|---|---|
| 도장 | 탈락·벌칙·낙찰 순간에 "탈락", "벌칙", "낙찰" 도장이 비스듬히 **쾅** 찍힌다 (살짝 흔들리는 화면) |
| 호외 헤드라인 | 라운드 결과를 신문 호외처럼 한 줄로: "[호외] 1표 차로 파랑 붕괴", "[속보] 올인했는데 동점" |
| 슬로모션 공개 | 결정적인 한 명(마지막 한 표, 최고액, 최고 숫자)은 일부러 뜸을 들여 천천히 공개한다 |
| 최종 시상식 | 게임 끝에 웃긴 상을 준다: 통수왕(배신 최다), 쫄보상(포기 최다), 텅장상(칩 탕진), 눈치 0단(다수파 최다) 등 |
| 휴대폰 반응 | 진동, 짧은 효과음(끌 수 있음), 탈락하면 내 화면에 도장 |
| 놀리는 문구 | 상황에 맞는 한마디를 여러 개 준비해 무작위로: "다들 생각이 똑같네", "표정 관리!" |

## 3. 게임별 규칙

### 3-1. 블라인드 경매

- **인원**: 2~15명 / **기본 라운드**: 10
- **한 줄 요약**: 한정된 칩으로 몰래 입찰해서, 가장 많이 건 사람이 그 라운드 점수를 가져간다.
- **진행**
  1. 모두 칩 100개로 시작한다.
  2. 라운드 시작 시 PC에 **이번 라운드 점수(1~3점)**를 공개한다.
  3. 각자 0~(남은 칩) 사이에서 몰래 입찰한다.
  4. 공개: 가장 많이 건 사람이 혼자면 그 사람이 점수를 가져간다.
- **칩**: 입찰한 칩은 이기든 지든 모두 사라진다.
- **동점·미제출**: 최고액이 동점이면 아무도 점수를 못 가져간다(칩은 사라짐). 미제출은 0 입찰.
- **최종 순위**: 점수 합계. 동점이면 남은 칩이 많은 사람이 위.
- **공개 연출**: 입찰액을 **작은 금액부터 한 명씩** 공개하고, 마지막에 최고액을 공개한다.
- **화면**: PC에는 라운드 점수, 입찰 현황(누가 냈는지), 공개, 순위표와 남은 칩. 휴대폰에는 남은 칩, 숫자 입력(빠른 버튼 +1/+5/+10/올인), 내 순위.
- **웃음 포인트**: 최고액이 동점이면 두 사람의 칩이 같이 **공중분해**되는 연출과 "[속보] 올인했는데 동점" 헤드라인. 3칩 이하로 낙찰되면 "헐값 낙찰" 도장(0칩 낙찰은 2명 이상이면 생길 수 없어 바꿈). 칩을 다 쓰면 이름 옆에 텅 빈 지갑.
- **만든 뒤 정한 것** (1단계)
  - 물건: 라운드마다 웃긴 물건(그림 41개)을 올린다. 일정표(물건·점수)는 처음부터 공개, 마지막 물건은 항상 3점
  - 돌발 물건(대기실에서 끌 수 있음): 미스터리 상자(0~5점, 공개 때 연다), 저주 물건(−2점, 최저가가 떠안음)
  - 봉투: 입찰하면 손이 봉투를 밀어 넣고, 금액을 바꾸면 봉투를 바꿔치기한다(금액은 비밀, 바꾼 사실만 보임)
  - 공개: 금액 순서대로 손이 칩 더미를 민다(0칩 빈손, 3칩까지 손가락, 시작 칩 40% 이상은 두 팔로 낑낑)
  - 진행: **휴대폰만으로 진행이 기본**(방장 휴대폰이 진행하며 참가, 모든 휴대폰에서 같은 순간 공개). PC 화면은 선택

### 3-2. 빨강 / 파랑

- **인원**: 3~15명 / **기본 라운드**: 10
- **한 줄 요약**: 빨강은 확실한 1점, 파랑은 과반이 모여야 3점.
- **진행**: 각자 빨강 또는 파랑 버튼을 몰래 누른다.
- **점수 (기본 규칙)**
  - 빨강: 무조건 +1
  - 파랑: 파랑을 누른 사람이 **전체 참가자의 과반(절반 초과)**이면 +3, 아니면 0
- **미제출**: 0점. 과반 계산의 분모(전체 참가자)에는 포함한다.
- **공개 연출**: 파랑 표가 한 칸씩 쌓이며 **과반선을 넘는지** 보여준다.
- **화면**: PC에는 과반선이 표시된 게이지, 순위표. 휴대폰에는 빨강/파랑 큰 버튼 두 개, 내 점수.
- **배신 요소**: 총점으로 순위를 겨루므로, 파랑이 아슬아슬하게 과반일 때 앞서가는 사람이 일부러 빨강을 누르면 파랑이 무너진다. 그러면 파랑을 누른 사람들은 0점, 자기는 1점이라 격차를 벌릴 수 있다. "믿어도 될까?"와 "누가 일부러 무너뜨렸나?"가 함께 생긴다.
- **변형 규칙을 두지 않는 이유**: "파랑이 성공하면 빨강도 보너스" 같은 변형은 빨강이 항상 더 이득(성공 시 4 > 3, 실패 시 1 > 0)이라 모두가 빨강만 누르게 되어 게임이 무너진다.
- **웃음 포인트**: 파랑이 **1표 차로** 과반에 못 미치면 게이지가 과반선 바로 앞에서 멈추는 슬로모션과 "[호외] 1표 차로 파랑 붕괴". 이어서 "범인은 이 안에 있다"며 빨강을 누른 사람들의 이름을 한 명씩 공개한다.
- **메모**: 라운드 사이의 대화(설득과 의심)가 재미의 핵심이다.

### 3-3. 가장 작은 유일한 숫자

- **인원**: 3~15명 / **기본 라운드**: 7
- **한 줄 요약**: 남과 겹치지 않은 숫자 중 가장 작은 걸 낸 사람이 이긴다. 단, 점수는 **내가 고른 숫자만큼**.
- **진행**: 각자 1~10 중 숫자 하나를 몰래 고른다.
- **판정**: 두 명 이상이 고른 숫자는 모두 무효. 남은(한 명만 고른) 숫자 중 가장 작은 숫자를 고른 사람이 승리.
- **점수**: 승자는 **자기가 고른 숫자만큼** 점수를 받는다. 작게 내면 이기기 쉽지만 점수가 적고, 크게 내면 점수가 크지만 지기 쉽다.
- **동점·미제출**: 유일한 숫자가 하나도 없으면 무승부. 미제출은 참가하지 않은 것으로 본다.
- **공개 연출**: PC에 1~10 숫자판을 띄우고, 숫자마다 고른 인원을 표시한다. 겹친 숫자는 지워지고, 남은 숫자 중 가장 작은 숫자가 강조된다.
- **화면**: PC에는 숫자판과 순위표. 휴대폰에는 1~10 버튼과 내 점수.
- **웃음 포인트**: 같은 숫자를 고른 사람들의 이름표가 숫자 칸에서 서로 부딪혀 튕겨 나가며 "다들 생각이 똑같네". 전원이 겹쳐 무승부가 되면 "[호외] 전원 눈치 실패".
- **메모**: 2명은 둘 다 1을 내는 것 말고는 선택지가 없어서 성립하지 않는다. 최소 3명.

### 3-4. 인디언 숫자

- **인원**: 2~10명 / **기본 라운드**: 10
- **한 줄 요약**: 내 숫자만 안 보인다. 남들 숫자, 남들 반응, **이미 나온 카드**를 보고 카드를 바꿀지 그리고 승부할지 정한다.
- **덱과 셈**
  - 덱은 **1~10 카드 여러 벌**이다. 2~4명 2벌, 5~6명 3벌, 7~8명 4벌, 9~10명 5벌.
  - 라운드에 쓴 카드(받은 카드, 교체로 버린 카드)는 모두 **버린 더미**로 가고 다시 나오지 않는다. 다음 라운드는 남은 덱에서 받는다.
  - PC에 **나온 카드 기록판**을 띄운다(숫자마다 몇 장 나왔는지 / 몇 장 있는지). 예: 2벌에서 10이 이미 2장 나왔다면, 내 카드는 10이 아니다.
  - 라운드를 시작할 때 남은 카드가 "인원 × 2"장보다 적으면 버린 더미를 섞어 새 덱을 만든다. PC에 "덱을 새로 섞었습니다"를 띄우고 기록판을 비운다.
- **라운드 진행 (두 단계)**
  1. **카드 받기**: 모두 칩 20개로 시작한다. 각자 카드 한 장을 받는다. 휴대폰에는 **다른 사람들 숫자만** 보이고 내 숫자는 가려진다. 참가비로 모두 칩 1개를 판에 낸다.
  2. **교체 단계**: 원하는 사람은 칩 1개를 판에 내고 덱에서 새 카드를 받는다(라운드당 1번). 버린 카드는 **바로 기록판에 공개**한다. PC에는 "○○님 카드 교체"가 뜨고, 다른 사람 휴대폰에는 새 숫자가 보인다. 진행자가 다음 단계로 넘긴다.
  3. **승부/포기 단계**: 각자 몰래 고른다. 바뀐 카드가 모두 반영된 상태에서 결정한다.
     - **승부**: 칩 3개를 판에 더 낸다.
     - **포기**: 칩 1개를 판에 낸다. 낮은 숫자 같으면 싸게 빠질 수 있다.
     - (이전 안 "승부 2 / 포기 2"는 포기가 승부보다 나은 경우가 없어 아무도 포기하지 않는다 — 이슈 #132)
  4. **공개**: 승부한 사람 중 숫자가 가장 큰 사람이 판의 칩을 모두 가져간다. 가장 큰 숫자가 동점이면 나눠 갖고, 나누고 남은 칩은 다음 라운드로 넘긴다.
  5. **최고 숫자 포기 벌칙**: 포기한 사람의 숫자가 이번 라운드 **전체에서 가장 컸다면(동점 포함)** 칩 5개를 승자에게 준다. 승자가 여러 명이면 나눠 갖고, 승자가 없으면(모두 포기) 판에 낸다.
- **판 이월**: 승부한 사람이 아무도 없으면 판의 칩은 다음 라운드로 넘어간다(판이 커진다).
- **칩이 모자랄 때**: 내야 할 칩보다 적게 남았으면 남은 칩을 모두 낸다(벌칙도 가진 만큼만). 남은 칩을 다 내고 승부하면 **올인 승부**로, 이겨도 판 전체를 받는다(부분 판은 두지 않는다 — 단순함 우선).
- **정산 순서** (이슈 #133): 참가비 → 교체 → 승부/포기 → 공개·승자 판정 → 판 분배 → 최고 숫자 포기 벌칙 분배 → 나누고 남은 칩 이월 → **탈락 확정** → 종료 판단.
  - 라운드 도중 칩이 0이 돼도 그 라운드는 끝까지 참여한다(올인 승부 가능). 탈락은 라운드 정산이 끝난 뒤 0칩인 사람만.
  - **마지막 라운드**(또는 1명만 남아 끝날 때)의 판에 남은 칩과 나누고 남은 칩은 **사라진다**. 최종 순위는 그 뒤 남은 칩으로 정한다.
  - 모두 0칩이 되면 마지막 라운드 시작 때 칩이 많았던 순으로 순위를 정하고, 같으면 공동 순위.
- **미제출**: 교체 단계는 교체 안 함, 승부/포기 단계는 포기로 본다.
- **최종 순위**: 남은 칩. 마지막 라운드가 끝나거나 1명만 남으면 종료.
- **공개 연출**: 승부한 사람들의 숫자를 작은 것부터 공개하고, 포기한 사람의 숫자는 마지막에 공개한다.
- **웃음 포인트**: 최고 숫자를 들고 포기한 사람에게 "벌칙" 도장과 "[호외] 10 들고 도망감". 카드를 바꿨는데 버린 카드가 10이었으면 기록판에 그 10이 크게 떨어지며 "아깝다…". 휴대폰에는 남의 숫자를 보여줄 때 "표정 관리!" 문구.
- **화면**
  - PC: 판의 칩, 단계 표시(교체/결정), 나온 카드 기록판, 교체한 사람, 결정한 사람, 공개, 순위표. **아직 공개되지 않은 숫자는 절대 표시하지 않는다.**
  - 휴대폰: 다른 사람 숫자 목록(교체되면 표시), 가려진 내 카드, 교체 버튼(교체 단계), 승부/포기 버튼(결정 단계), 내 칩.
- **메모**: 서로 얼굴을 보며 떠보는 대화가 핵심이다. 1회 결정으로 시작하고, 반응을 보고 2단계 베팅(올리기)을 검토한다.

### 3-5. 라이어 다이스

- **인원**: 2~6명 / **진행**: 마지막 1명이 남을 때까지
- **한 줄 요약**: 내 주사위만 보고 "전체에 ○가 ○개 이상"을 불러 올린다. 의심되면 버튼을 누른다.
- **진행**
  1. 각자 주사위 5개를 굴린다. 휴대폰에만 내 주사위가 보인다.
  2. 차례인 사람이 "개수 × 눈"을 부른다(예: 4가 5개 이상). 직전보다 커야 한다: 개수를 늘리거나, 같은 개수에서 더 큰 눈.
  3. 다음 차례인 사람은 **더 크게 부르기** 또는 **"의심" 버튼** 중 하나를 누른다.
  4. 의심하면 모든 주사위를 공개한다. 실제 개수가 부른 개수 이상이면 의심한 사람이, 아니면 부른 사람이 주사위 1개를 잃는다.
  5. 주사위를 잃은 사람부터 새 판을 시작한다. 주사위가 0개가 되면 탈락.
- **의심 버튼은 다음 차례인 사람만** 누를 수 있다(속도 싸움 방지). 아무나 누르는 방식은 실시간 통신으로 바꾼 뒤에 검토한다.
- **차례 시간**: 진행자가 차례를 넘길 수 있게 한다(자리 비운 사람 대비).
- **옵션**: 1을 만능(모든 눈으로 셈)으로 할지. 기본은 끔.
- **공개 연출**: PC에 모든 사람의 주사위를 펼치고, 부른 눈과 같은 주사위를 하나씩 세어 올린다.
- **화면**: PC에는 차례 표시, 지금까지 부른 기록, 각자 남은 주사위 개수, 공개 연출. 휴대폰에는 내 주사위, 부르기 입력(개수·눈), 의심 버튼(내 차례일 때만).
- **웃음 포인트**: 거짓말이 들키면 그 사람 이름 옆의 코가 쭉 길어지고(피노키오) "[속보] 거짓말 적발". 의심했는데 틀리면 의심한 사람에게 "생사람 잡기" 도장. 주사위 공개는 컵을 엎어 주사위가 굴러 나오는 움직임으로.

## 4. 공통 기반 (게임을 만들기 전에 한 번)

### DB (SQL 한 번 실행)

- `game_rooms.game`: 방의 게임 종류
- `game_rooms.settings` (JSONB): 라운드 수, 옵션 같은 진행자 설정
- `game_rooms.state` (JSONB): 게임별 방 상태(라운드 점수, 판의 칩, 부른 기록 등)
- `game_players.data` (JSONB): 사람별 상태(점수, 칩, 주사위·카드 같은 비밀 정보)
- `game_moves` 테이블: 라운드별 제출(입찰액, 버튼, 숫자, 승부/포기). 기존 `game_votes`는 A/B만 받도록 막혀 있어 새 게임은 이 테이블을 쓴다

비밀 정보는 서버에서만 읽고, **본인에게 필요한 만큼만** 응답에 담는다(인디언 숫자는 본인 숫자를 빼고, 라이어 다이스는 본인 주사위만).

### 서버

- 공통 라운드 도구: 라운드 시작, 제출 받기(1인 1제출, 공개 전 변경 가능), 조건부 마감(중복 공개 방지)
- 공통 점수판: 점수와 순위 계산, 동점 처리 규칙을 게임별로 받기
- 게임 규칙은 순수 함수로 분리하고 `node --test`로 단위 테스트

### 화면

- 공통 대기실(QR, 참가자 목록, 내보내기, 시작, 진행자 설정)과 공통 참가 화면(닉네임)을 `shared/`로 분리하고, 소수결도 이걸 쓰도록 옮긴다
- 공통 순위표, 3·2·1 카운트다운, 순차 공개 연출 도구
- 투표 순차 전송, 늦게 온 응답 무시 같은 실서버 대응은 공통 도구로 제공

### 테스트

- 게임마다 Playwright 시나리오: 진행자 1명 + 참가자 여러 명, **응답 지연을 흉내 낸 테스트** 포함
- 규칙 단위 테스트: 동점, 미제출, 경계값(칩 0, 2명, 15명)

## 5. 혼자 하는 게임 (별도 트랙)

서버 없이 브라우저 안에서만 도는 게임. **물리 때문에 생기는 웃긴 장면**이 핵심이다. 아래 참고작은 아이디어만 참고하고, 코드와 그림은 직접 만든다(필요하면 무료 CC0 모델인 Kenney 사용).

| 게임 | 참고 | 핵심 | 웃음 포인트 |
|---|---|---|---|
| 터키 아이스크림 | x282665.com의 トルコアイス3D | 장수가 되어 손님이 콘으로 낚아채려는 아이스크림을 피한다. 버틴 시간이 점수 | 흐느적거리는 물리 팔, 부딪히면 부서지는 포장마차, 빼앗기는 순간 슬로모션 |
| 소프트아이스크림 쌓기 | softserve.nog.cc의 ソフトクリームシミュレーター | 기계에서 나오는 아이스크림을 콘을 움직여 똑바로 높이 쌓는다. 높이(cm)가 점수 | 휘청이다가 탑째로 쏟아지는 순간, 기록 직전의 아슬아슬함 |

공통: 최고 기록 저장, 결과 공유(스크린샷), 휴대폰·PC 모두 지원. 1차는 2D로 재미를 확인하고, 2차에서 3D 연출을 붙인다.
