# 006 — 대기실 숫자 설정 연타가 같은 값으로 중복 저장됨

**우선순위:** P2

**분류:** 구현 결함 / 공통 대기실, 경매 도입 전 수정

**상태:** 미해결

## 근거

- `public/game/shared/lobby.js:93-103`: 증가·감소 값을 마지막 서버 응답의 `current[field.key]`에서 계산하고 완성된 patch를 큐에 넣는다.
- `public/game/shared/lobby.js:114-139`: `current`는 서버 상태를 다시 그릴 때만 바뀐다.
- `test/e2e/lobby-settings.spec.js`: 다른 종류의 설정을 연달아 바꾸는 테스트는 있지만 같은 숫자 설정 연타는 없다.
- `docs/minigame_roadmap.md`의 1단계에서 라운드 수 설정의 실제 저장을 연결할 예정이다. 현재 소수결 `settings`는 비어 있어 아직 실제 게임 설정으로 노출되지 않는다.

## 재현과 영향

라운드 수가 10이고 저장 응답이 느릴 때 `+`를 두 번 누르면 두 이벤트가 모두 `current.rounds === 10`을 읽는다. 큐는 순서를 지키지만 `{ rounds: 11 }`, `{ rounds: 11 }`을 보낸다. 사용자가 의도한 12가 저장되지 않는다. `+` 뒤 `-`도 최종 10이 아니라 9를 보낼 수 있다.

최소 DOM 대역으로 대기실을 마운트하고 초기 상태 10에서 연속 두 번 증가시켰다. 실제 콜백 인자는 `[11, 11]`이었다.

## 수정 방향

서버 확정값과 사용자의 최신 의도값을 분리하여 다음 증가·감소를 대기 중 의도값에서 계산한다. 폴링의 과거 값이 의도값을 덮어쓰지 않게 하고, 저장 실패 시에는 명시적으로 알린 뒤 값과 대기 상태를 일관되게 복구한다. 시작 시 미저장 설정을 어떻게 처리할지도 동일한 계약으로 정한다.

## 완료 기준

- [ ] 지연 저장 상태에서 `+,+`는 10→12, `+,-`는 10→10으로 귀결된다.
- [ ] 빠른 연타에서도 최소·최대 범위를 벗어나지 않는다.
- [ ] 중간 폴링 응답이나 앞 요청 실패가 최신 입력을 조용히 버리지 않는다.
- [ ] 경매 도입 시 실제 저장을 확인하는 테스트에 연타·실패·시작 경합을 포함한다.
