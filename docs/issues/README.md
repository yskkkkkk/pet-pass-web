# 코드·계획서 점검 이슈

점검일: 2026-10-24

현재 코드와 `docs/minigame_plan.md`, `docs/minigame_roadmap.md`, `docs/minigame_structure.md`를 대조한 로컬 이슈 목록이다. 아래 번호는 파일 식별자이며 GitHub Issue 번호가 아니다. 이번 작업은 문제 기록만 수행하며 서비스 로직이나 게임 규칙을 바꾸지 않는다.

## 분류와 우선순위

- **구현 결함**: 현재 코드의 동작을 격리 실행으로 확인한 문제.
- **설계 결정 필요**: 아직 구현하지 않은 게임의 규칙 충돌·누락. 미구현 자체를 버그로 취급하지 않는다.
- **P1**: 인증 결과·게임 판정·참가 조건·검색 결과의 정확성에 영향을 주거나, 예정된 게임의 핵심 선택 구조를 무너뜨리는 문제.
- **P2**: 다음 단계 구현 전에 보완할 공통 UI, 백업 또는 정산 명세 문제.

## 확인 범위와 한계

- 게임 API·메모리/Supabase 저장소 구현·소수결 화면·공통 대기실, 매장 조회 화면·동기화 배치, 동물 조회 API와 관련 문서를 읽었다.
- 기존 단위 테스트 132개와 SQL 테스트 6개는 통과했다. 기존 테스트 통과가 아래 경계 상황의 정확성을 보장하지는 않는다.
- 구현 결함 8건은 핸들러 직접 호출, 저장소 작업 지연·실패 주입, 브라우저 코드의 격리 실행 또는 외부 API·파일시스템 모의 응답으로 확인했다. 실제 운영 DB나 정부 API를 호출하거나 운영 데이터를 변경하지 않았다.
- 화면 관련 재현은 순수 로직 또는 최소 DOM 대역을 사용했다. 실제 브라우저 E2E·Supabase 동시성 검증까지 수행한 것으로 해석하면 안 된다. 각 파일의 완료 기준에 후속 회귀 테스트를 명시했다.
- 아직 예정 단계인 경매·빨강/파랑·숫자 게임·인디언 숫자·라이어 다이스의 미구현 항목은 중복 이슈로 만들지 않았다. 보안 전수 감사나 전체 기능의 무결성 보증을 의미하지 않는다.

## 처리 순서

공통 게임 기반의 001~004를 우선 처리하고, 002·003은 같은 트랜잭션 경계를 공유하도록 설계한다. 005·008은 기존 펫패스 기능의 독립적인 정확성 문제다. 006은 경매의 라운드 수 설정을 연결하기 전에, 009·010은 인디언 숫자 규칙 엔진을 만들기 전에 해결한다.
