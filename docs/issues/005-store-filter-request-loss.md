# 005 — 매장 로딩 중 변경한 검색·필터 요청이 유실됨

**우선순위:** P1

**분류:** 구현 결함 / 펫패스 검색 화면

**상태:** 미해결

## 근거

- `public/script.js:660-662`: 기존 요청 중이면 새 `fetchStoresPage` 호출을 즉시 버린다.
- `public/script.js:680-709`: 기존 요청의 결과를 현재 필터와 무관하게 목록·지도에 반영한다.
- `public/script.js:815-821`: 실제 요청이 실행되는지와 관계없이 `lastFilterKey`를 먼저 갱신한다.

## 재현과 영향

1. 네트워크 지연을 두고 전국 매장 또는 이전 검색 결과를 로딩한다.
2. 응답 전에 지역·카테고리 또는 검색어를 변경한다.
3. 필터 UI와 `lastFilterKey`는 새 조건이지만 새 요청은 `isLoadingStores` 때문에 무시된다.
4. 이전 응답이 도착하면 새 필터 아래에 이전 조건의 목록과 지도 마커가 표시된다.
5. 같은 조건으로 `applyFilters()`를 다시 호출해도 키가 같아 재요청되지 않는다.

격리 실행에서 진행 중 요청 하나를 둔 상태로 검색어를 변경하고, 응답 후 같은 조건을 재적용했다. fetch 호출은 총 1회였으며 목록에는 이전 조건의 매장이 남았다. 더 보기 요청 도중 필터 변경에도 같은 문제가 있다.

## 수정 방향

필터 스냅샷과 요청 세대를 구별하고, 로딩 중 변경한 최신 필터를 대기시키거나 이전 요청을 취소해 반드시 처리한다. 이전 필터의 응답은 버리고, 더 보기 응답도 같은 필터 세대에만 이어 붙인다. 실패했거나 시작하지 않은 요청의 키를 성공적으로 반영한 키처럼 취급하지 않는다.

## 완료 기준

- [ ] 느린 요청 도중 검색·지역·카테고리를 여러 번 바꿔도 마지막 조건의 결과가 표시된다.
- [ ] 이전 응답이 뒤늦게 도착해 목록·지도·건수·offset을 덮어쓰지 않는다.
- [ ] 더 보기 도중 필터를 바꾸면 다른 조건의 페이지가 섞이지 않는다.
- [ ] 요청 실패 후 같은 필터로 정상 재시도가 가능하다.
- [ ] 지연 응답과 연속 입력을 포함하는 화면 회귀 테스트를 추가한다.
