# 007 — 전체 매장 백업을 변경분으로 덮어씀

**우선순위:** P2

**분류:** 구현 결함 / 데이터 동기화·복구 자료

**상태:** 미해결

## 근거

- `scripts/sync-stores.js:345-348`: 변경이 없고 좌표가 있는 기존 매장은 건너뛰므로 `toUpsert`에 포함되지 않는다.
- `scripts/sync-stores.js:439-447`: “8. 로컬 백업” 단계는 `data/stores.json`에 `JSON.stringify(toUpsert, ...)`를 저장한다.
- `DEPLOY.md` 5장은 `data/stores.json`을 동기화 결과의 로컬 백업으로 설명한다.
- `.github/workflows/daily_sync.yml`은 이 파일을 저장소에 커밋한다.

## 재현과 영향

1. DB와 원본 엑셀에 동일한 정상 매장 1개가 있고 좌표도 있는 상태를 만든다.
2. 변경 없이 동기화한다.
3. 결과는 `success: true`, `upserted: 0`이지만 백업 파일은 `[]`로 덮어써진다.

엑셀·DB 응답과 파일시스템을 모의 처리한 격리 실행으로 위 결과를 확인했다. 일부 매장만 바뀐 배치에서는 변경된 매장만 남는다. 런타임은 이 파일을 읽지 않으므로 즉시 매장 조회가 비는 문제는 아니지만, 전체 백업으로 복구하거나 배치 전후를 비교할 수 없게 된다.

## 수정 방향

UPSERT 변경분과 전체 최종 스냅샷을 분리한다. DB 반영이 성공한 뒤 전체 결과를 저장하거나, 검증된 원본과 기존 행을 병합해 최종 상태를 구성한다. 전체 스냅샷 확보 실패 시 기존 정상 백업을 보존하고 경고를 기록한다. 파일을 단순 변경분으로 유지하려면 이름·문서·복구 절차를 변경해야 하므로 백업이라는 현재 계약을 먼저 확인한다.

## 완료 기준

- [ ] 무변경 배치 후에도 기존 전체 매장이 백업에 남는다.
- [ ] 신규·수정·삭제가 섞인 배치의 백업이 최종 DB 내용과 일치한다.
- [ ] 백업 생성 실패로 기존 정상 파일이 빈 파일이나 부분 파일로 대체되지 않는다.
- [ ] UPSERT 최적화와 “부가 백업 실패는 DB 동기화 성공을 바꾸지 않음”이라는 기존 동작은 유지한다.
- [ ] 모의 DB/파일시스템으로 무변경·부분 변경·삭제·백업 실패를 회귀 테스트한다.
