# 009 — 인디언 숫자에서 포기는 승부에 약하게 지배됨

**우선순위:** P1

**분류:** 설계 결정 필요 / 인디언 숫자 구현 전

**상태:** 규칙 결정 대기

## 근거

- `docs/minigame_plan.md:100-104`: 승부와 포기는 모두 칩 2개를 내며, 승부한 사람만 판을 받을 수 있다.
- 같은 부분: 최고 숫자로 포기하면 추가 벌칙 5개가 있지만 승부에는 해당 벌칙이 없다.
- `docs/minigame_plan.md:114`: 상대 반응을 보고 승부/포기를 판단하는 대화를 핵심 재미로 제시한다.
- `docs/minigame_roadmap.md` 4단계에서 규칙 엔진과 포기 벌칙을 구현할 예정이다.

## 문제

다른 사람들의 선택과 카드가 같다고 고정하면, 내 포기를 승부로 바꿨을 때 내 칩 수가 줄어드는 경우가 현재 명세에 없다. 참가비와 교체비는 이미 낸 비용이며 두 행동 사이 차이를 만들지 않는다.

| 상황 | 포기 | 승부 |
|---|---|---|
| 내가 최대 숫자가 아님 | 2개 지출, 당첨 불가 | 2개 지출, 질 수도 있으나 추가 손해 없음 |
| 내가 전체 최대 숫자 | 2개 지출 + 최대 5개 벌칙 | 2개 지출 후 판 수령 또는 분배 |
| 다른 사람이 모두 포기 | 판을 다음 라운드로 이월 | 내가 유일한 승부자로 판 수령 |

따라서 포기는 승부에 **약하게 지배되는 선택**이다. 플레이어가 규칙을 이해하면 매번 승부하는 것이 손해가 없고, 숨겨진 내 숫자를 추론하거나 포기를 유도하는 장치의 의미가 약해진다. 미제출 자동 포기와 실수는 남겠지만 의도적인 선택의 유인이 되지는 않는다.

이는 실행 중 버그가 아니라 현재 명세의 보상 구조 분석이다. 아직 구현되지 않은 기능을 결함으로 간주한 것은 아니다.

## 결정할 사항

포기에 비용 절감이나 다른 명확한 이익을 줄지, 승부에 추가 위험을 둘지, 아니면 포기를 전략 선택이 아닌 연출용 행동으로 의도할지 결정한다. 어느 쪽이든 기존 계획의 동일 비용·최고 숫자 포기 벌칙을 함께 재평가해야 한다. 여기서 임의로 규칙을 변경하지 않는다.

## 완료 기준

- [ ] 승부가 더 나은 상황과 포기가 더 나은 상황의 구체적인 칩 정산 예시를 각각 정의한다. 전략 선택이 의도가 아니라면 목표와 UX를 명시적으로 수정한다.
- [ ] `minigame_plan.md`의 비용·벌칙·설명과 `minigame_roadmap.md`의 테스트 항목을 같은 결정으로 갱신한다.
- [ ] 칩 부족·동점·모두 포기에서도 선택 간 보상 차이가 의도대로 유지된다.
- [ ] 규칙 엔진 구현 시 결정한 보상 사례를 순수 함수 테스트로 고정한다.
