# 010 — 인디언 숫자의 올인·탈락·최종 이월금 정산 순서 미정

**우선순위:** P2

**분류:** 설계 결정 필요 / 인디언 숫자 구현 전

**상태:** 규칙 결정 대기

## 근거

- `docs/minigame_plan.md:98-106`: 참가비·교체비·승부/포기비·벌칙을 순서대로 지불하며, 부족하면 전액 지불하고 0칩이면 탈락한다.
- `docs/minigame_plan.md:103-108`: 동점 분배 잔여분과 모두 포기한 판은 다음 라운드로 이월하지만, 최종 라운드 또는 1명 생존 시 종료한다.
- `docs/minigame_roadmap.md:56-65`: 칩 부족·탈락·이월 테스트가 예정되어 있으나 결과를 결정할 상세 계약은 없다.

## 결정되지 않은 경계 사례

**0칩 판정 시점:** 칩 3개인 사람이 참가비 1개와 승부비 2개를 내면 공개 직전에 0개다. “0개면 탈락”을 즉시 적용하면 이번 판을 이길 자격도 사라질 수 있고, 정산 뒤 적용하면 판을 받아 살아남을 수 있다. 칩 1개로 참가비를 낸 사람, 마지막 1개로 카드를 교체한 사람도 이후 입력·카드 보유·승자 자격이 불명확하다. 모두 참가비로 0이 되면 0명 생존 처리도 필요하다.

**최종 이월금:** 마지막 라운드에서 모두 포기하거나, 판 7개를 동점 승자 2명이 나누면 다음 라운드로 넘기라고 한 금액이 남는다. 하지만 다음 라운드는 없다. 남은 1명으로 조기 종료하는 경우도 같다. 최종 순위가 남은 칩 기준이므로 배분·소멸 여부가 결과를 바꾼다.

이 선택들은 서로 다른 구현이 모두 가능하다. 지금 임의의 기대값으로 테스트를 작성하면 엔진·화면·최종 순위가 각기 다른 규칙을 채택할 수 있다.

## 수정 방향

라운드 참가 확정 → 각 비용 납부 → 카드/선택 확정 → 승자 판정 → 판 분배 → 포기 벌칙 분배 → 잔여금 처리 → 탈락 확정 → 종료 판단의 순서를 명문화한다. 실제 순서는 설계 결정에 따르되, 각 시점의 참가 자격과 칩 보존/소멸 규칙을 분명히 한다. 009에서 바뀔 수 있는 비용 구조와 함께 확정한다.

## 완료 기준

- [ ] 시작 칩 1·2·3·4개, 교체 유무, 승부/포기의 결과 표를 정의한다.
- [ ] 비용을 내고 0개가 된 사람의 이번 라운드 승자 자격과 관전 전환 시점을 정한다.
- [ ] 벌칙을 낼 칩이 부족한 경우의 실제 분배액과 동점 잔여분을 정의한다.
- [ ] 마지막 라운드·1명 생존·0명 생존에서 남은 판과 나눗셈 잔여분 처리 및 최종 순위를 정한다.
- [ ] 정산 전후의 플레이어 칩 합계와 판의 합계가 명시된 보존/소멸 규칙을 만족하도록 테스트한다.
